## 2. Cambios detallados

### 2.1 Build (`pom.xml`)

- **Lombok**: se corrigió la definición de la dependencia, que tenía un error de sintaxis y no compilaba. La versión quedó fijada en `1.18.48` mediante la propiedad `lombok.version`.
- **Procesamiento de anotaciones en JDK 23+**: se agregó `maven-compiler-plugin 3.13.0` con `<proc>full</proc>`, porque desde JDK 22 el procesamiento de anotaciones ya no se habilita automáticamente. Sin esto, Lombok no genera los getters/setters y el proyecto no compila por línea de comandos.
- **Nuevas dependencias**: `springdoc-openapi-starter-webmvc-ui` (documentación) y `com.h2database:h2` (base de datos en memoria, solo `runtime`).

### 2.2 Documentación OpenAPI / Swagger

- **springdoc 2.0.4**: es la línea compatible con Spring Boot 3.0.x. Versiones más nuevas exigen Spring Framework 6.2 (usan `LiteWebJarsResourceResolver`) y la aplicación no arranca sobre Boot 3.0.6.
- **`config/OpenApiConfig.java`**: clase de configuración que publica los metadatos globales (título *Clients API*, descripción y versión `1.0.0`) en la cabecera del Swagger UI.
- **`ClientController`**: cada endpoint quedó anotado con `@Tag`, `@Operation` (summary/description), `@Parameter` (para el `id` del delete) y `@ApiResponses` documentando los códigos: `200/400` en creación, `204/404` en eliminación, `200` en el listado.
- **DTOs**: `ClientDto` y `ServiceResponse` describen sus campos en el esquema OpenAPI.
- **URLs publicadas**:
  - Swagger UI → `http://localhost:8080/swagger-ui.html`
  - Documento OpenAPI (JSON) → `http://localhost:8080/v3/api-docs`
- Configuradas en `application.properties` vía `springdoc.swagger-ui.path` y `springdoc.api-docs.path`.

### 2.3 Base de datos y configuración

Se mantiene `mssql-jdbc` (SQL Server) como dependencia de producción, pero para desarrollo y pruebas locales se usa **H2 en memoria**, sin instalar nada:

```properties
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.url=jdbc:h2:mem:exam;DB_CLOSE_DELAY=-1
spring.datasource.username=sa
spring.datasource.password=
spring.jpa.hibernate.ddl-auto=none
spring.jpa.open-in-view=false
spring.sql.init.mode=always
```

- La capa de datos es basada en `JdbcTemplate`; Hibernate está en el classpath por `spring-boot-starter-data-jpa` pero **no** gestiona entidades, por eso `ddl-auto=none`.
- **`schema.sql`**: el script original creaba la tabla sin especificar las columnas. Ahora la define explícitamente, con los mismos nombres que usa el SQL del `JdbcTemplate`:

```sql
CREATE TABLE IF NOT EXISTS clients (
    id         INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    first_name VARCHAR(60),
    last_name  VARCHAR(60),
    surname    VARCHAR(60),
    phone      VARCHAR(60)
);
```

### 2.4 Nuevo endpoint DELETE

| Método | Ruta | Éxito | No encontrado |
|--------|------|-------|---------------|
| `DELETE` | `/api/client/{id}` | `204 No Content` | `404 Not Found` |

- **Controller**: `deleteClient(@PathVariable Long id)` retorna `ServiceResponse` con `success=true, message="Client deleted with sucesss"` (204) o `success=false, message="Client not found"` (404).
- **Service** (`IClientService` / `ClientService`): `int deleteClient(Long id)`, delega al repositorio y retorna el número de filas afectadas.
- **Repository** (`IClientRepository` / `ClientRepository`): `deleteClient(Long id)` ejecuta `delete from clients where id = ?` sobre `JdbcTemplate`.

## 4. Dificultades encontradas y cómo se resolvieron

- **El proyecto no compilaba**: el `pom.xml` original tenía un error de sintaxis en la dependencia de Lombok. Se corrigió y se fijó la versión `1.18.48`.
- **No compilaba por línea de comandos en JDK 23+**: el procesamiento de anotaciones estaba deshabilitado por defecto. Se resolvió con `maven-compiler-plugin 3.13.0` + `<proc>full</proc>`.
- **springdoc más reciente rompe el arranque**: al exigir Spring Framework 6.2 sobre Boot 3.0.6. Se quedó en springdoc `2.0.4`.
- **El script SQL no creaba la tabla esperada**: no especificaba columnas y no coincidía con el SQL del repositorio. Se reescribió `schema.sql` con columnas explícitas.
- **Sin proveedor de Bean Validation**: `spring-boot-starter-web` ya no trae implementación desde Boot 3.0; la anotación llega por `hibernate-core` pero se ignora en silencio. Se agregó `spring-boot-starter-validation` y se cubrió con `BeanValidationProviderTest`.

## 5. Mejoras que podrían aplicarse

- Mapear `Client` ↔ `ClientDto` con MapStruct (ya está la dependencia) en lugar del mapeo manual del `ClientService`.
- Agregar validación de Bean Validation en el DTO del create (`@NotBlank` en `firstName`, `lastName`, `phone`) y manejarlo con `@Valid` + `400`.
- Devolver `201 Created` en lugar de `200` al crear un cliente.
- Los servicios capturan y relanzan excepciones vacías (`catch (Exception ex) { throw ex; }`): se pueden eliminar.
- Migrar de `JdbcTemplate` a Spring Data JPA si se requiere más lógica de dominio.
- Exponer la documentación con autenticación si el API deja de ser solo de prueba.
